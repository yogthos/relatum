# Types

A declared type decides what a column accepts and, in one case, what it
coerces to. Types are parsed by `relatum.type` and enforced in two places: at
insert time by the schema layer, and continuously by the engine's check
constraints.

```clojure
(require '[relatum.schema :as s])

(s/parse-type "varchar(32)")  ;; => {:kind :varchar, :max-length 32, :sql "varchar(32)", ...}
(s/parse-type :int)           ;; => {:kind :int, :sql "int", ...}
(s/known-types)               ;; => ["bool" "date" "int" "keyword" "real" "text"
                              ;;     "timestamp" "uuid" "varchar"]
```

Strings and keywords both work, case-insensitively.

## The vocabulary

Text:

- `"text"`, `"string"` — any string.
- `"varchar(n)"`, `"char(n)"` — a string of at most n characters. Oversized
  values reject with `:too-long`, and the error carries
  `:max-length` and the actual `:length`.
- Bare `"varchar"` or `"char"` without the length is unbounded text. Say
  `"varchar(64)"` when you want the bound, `:text` when you don't.

Integers:

- `"int"`, `"integer"`, `"bigint"`, `"smallint"`, `"long"` — any integer.
  A float like `1.5` rejects, a string like `"3"` rejects.

Real numbers:

- `"real"`, `"double"`, `"float"`, `"decimal"`, `"numeric"` — any number,
  coerced to a double on the way in. An integer `3` becomes `3.0`.

Others:

- `"bool"` / `"boolean"` — true or false.
- `"uuid"` — a `java.util.UUID` object. On jolt, `(java.util.UUID/randomUUID)`
  and `(java.util.UUID/fromString "...")` both produce them.
- `"keyword"` / `"kw"` — a Clojure keyword.
- `"date"` — a `java.time.LocalDate` object.
- `"timestamp"`, `"datetime"`, `"instant"` — a `java.time.Instant` object.

The date, timestamp and uuid kinds check for the host object with
`instance?`. A string like `"2026-01-01"` does not parse into a date, it
rejects with `:bad-type`. Construct the object first if your data arrives as
text.

## What a rejection looks like

Row validation goes through `s/coerce-row`, which throws ex-info whose ex-data
carries `:relatum/error` plus the details:

```clojure
(s/coerce-row (s/table :person) {:id 1 :name "Ada" :balance "many"})
;; ExceptionInfo Column :balance of :person expects real, got "many" (text)
;; ex-data => {:relatum/error :bad-type
;;             :table :person :column :balance
;;             :expected "real" :value "many" :actual-type "text"}
```

The error keywords a value can produce:

- `:bad-type` — the value is the wrong shape for the column.
- `:too-long` — a varchar over its bound.
- `:required` — a nil where the column demands a value.
- `:unknown-column` — a key the table never declared.

## Judging values directly

Two helpers answer the same question without the exception machinery:

```clojure
(s/conforms? (s/parse-type :int) 3)          ;; => true
(s/conforms? (s/parse-type :int) 3.5)        ;; => false
(s/varchar-conforms? 4 "abcd")               ;; => true
(s/varchar-conforms? 4 "abcde")              ;; => false
```

## The jolt note behind `:real`

Only `:real` carries a type hint, and only because jolt coerces `^double`. On
jolt the `^long` hint would be a contract that neither coerces nor rejects,
so integer columns are enforced by validation instead of by the record
constructor. That is also why the record type generated by `create-table`
hints non-nullable `:real` fields and nothing else.
